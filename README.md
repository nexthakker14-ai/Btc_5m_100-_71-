# BTC 5m — Telegram signal bot

Бот аналізує BTC_USDT perpetual futures на MEXC за 5-хвилинними свічками. У `patterns.json` залишено рівно 9 заданих 11-свічкових патернів. Бот **не має торгових API-ключів і не відкриває угоди**.

## Як запустити локально

1. Створи Telegram-бота через [@BotFather](https://t.me/BotFather).
2. Встанови Python 3.12+.
3. Виконай:

```bash
pip install -r requirements.txt
```

4. Задай `BOT_TOKEN` (нікому не показуй токен):

```powershell
# Windows PowerShell
$env:BOT_TOKEN="токен_від_BotFather"
python bot.py
```

```bash
# Linux/macOS
export BOT_TOKEN="токен_від_BotFather"
python bot.py
```

5. Відкрий Telegram-бота і надішли `/start`.

Команди: `/start`, `/status`, `/stats`, `/help`.

## Розгортання на GitHub + Railway

1. Створи GitHub-репозиторій і завантаж усі файли з архіву.
2. У Railway створи проєкт **New Project → Deploy from GitHub Repo**.
3. У **Variables** додай `BOT_TOKEN` зі свого @BotFather.
4. Рекомендовано додати Railway Volume та змонтувати його в `/data`, щоб зберігати стан і статистику після перезапусків.
5. Після Deploy відкрий Telegram і надішли `/start`.

Railway використовує `Dockerfile` та `railway.json`. MEXC API key/secret не потрібні — використовуються публічні ринкові дані.

## Логіка сигналів

- Бот шукає **рівно 9 патернів** із `patterns.json`. Кожен патерн — це точна послідовність **11 сусідніх закритих 5-хвилинних свічок**. Пропуски свічок не допускаються.
- Напрямок `LONG` або `SHORT` заданий для кожного патерну.
- Щойно закривається 11-та свічка патерну, бот одразу надсилає `SIGNAL`. Додаткового етапу підтвердження немає.
- Після сигналу перевіряються **наступні 5 закритих свічок**. Для `LONG` сприятлива свічка зелена, для `SHORT` — червона.
- Якщо сприятлива свічка з'явилась першою на 1-й, 2-й, 3-й, 4-й або 5-й свічці перевірки, бот надсилає відповідно `WIN 1/5`, `WIN 2/5`, `WIN 3/5`, `WIN 4/5` або `WIN 5/5`.
- Якщо всі 5 свічок протилежного кольору — `LOSS 5/5`.
- Doji не вважається ні зеленою, ні червоною. Якщо сприятливого кольору не було, але була doji, результат позначається `VOID`, а не `LOSS`.
- Якщо в послідовності даних є пропуск 5-хвилинної свічки, поточна перевірка позначається `VOID`, а історія для пошуку патернів починається заново.
- Під час першого запуску бот бере останні 10 свічок лише як початкову історію і не надсилає сигнали, що завершилися до запуску.
